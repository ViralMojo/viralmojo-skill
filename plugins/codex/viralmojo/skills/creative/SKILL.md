# Creative

This is one of ViralMojo's four companion skills. The standing rules and host routines every ViralMojo skill assumes — confirm before writing, never invent, the workspace anchor, job polling inside 45 seconds — live in `$viralmojo`: load it first if it is not loaded in this session.

Pick the one skill below whose description matches the request and read its file before doing the work — its instructions are the web agent's, byte for byte. Load one skill for the work in front of you, not every skill the ask brushes against.

| Skill | File | What it does and when to use it |
|---|---|---|
| `creative-writing` | `references/creative-writing/creative-writing.md` | Writes creative deliverables in the conversation — hooks, scripts, ad copy, headlines, and variations of any of them — grounded in the brand's own customer language, personas, and messaging direction, and against a brief when one is named. Deliverables live in chat and are saved only on request. Use when the user asks for hooks, a script, copy, headlines, rewrites, or more variations of any of these — including ad copy modeled on a reference creative. Not for packaging a concept into a brief or a test plan for production; that's brief drafting. Not for the finished static ad — the generated image with its copy; that's static ads. |
| `iterations` | `references/iterations/iterations.md` | Recommends the highest-confidence next moves on a performing ad — either picking which ads deserve the effort first, or building the actual recommendations once one is chosen. Use when the user asks which ads to iterate on this week or month, hands over a specific ad and asks how to iterate it, asks how to extend a winner's life, or asks what to test next on an ad that's performing well. Not for a first script, a first headline, or any concept written from scratch — that's creative writing. Not for making the new version of a static itself — that's static ads. |
| `static-ads` | `references/static-ads/static-ads.md` | Makes finished static image ads for the brand's own product — the generated image together with its primary text, headline, description, call to action and what the ad tests — by filling one proven static-ad template with the brand's look, its real product photos and real proof from the workspace. Use when the user asks for a static ad, an image ad or ad creatives to run; asks to turn a brief's test cells or a banked idea into ads; hands over a competitor ad, a swipe-file entry or a winning ad of their own and wants one made like it; or asks to change, resize or redo an ad already made. Not for copy, hooks, headlines or scripts wanted as words in chat — that's creative writing; not for packaging a concept for production — that's brief drafting; not for deciding what to change on a performing ad — that's iterations. |
| `brand-assets` | `references/brand-assets/brand-assets.md` | Keeps the brand's look on file in Brand Assets — builds and maintains the Brand DNA doc (typefaces, colours with hex, photography direction, product details, ad style) from one read of the brand's own site and the photos already kept, keeps the product photos and the logo the user uploads (one folder per product inside Brand Assets), judges whether an unnamed upload is a brand asset at all, and adds a new product's details to the doc. Use when the user asks to build, fill, fix, correct, update or rebuild Brand DNA or the brand's look; uploads or sends product photos or a logo, named or not; or when another skill finds Brand DNA empty or needs an upload kept. Not for making ads — static-ads makes them and only reads what this keeps. |

Each skill's own links (`references/<file>.md`) resolve inside that skill's folder here: `references/creative-writing/references/<file>.md`. When a skill says to call `load_skill` with another skill's name, open that skill's file through its companion — `$research`, `$creative`, `$strategy` or `$performance` — and when it says `read_skill_reference`, open the file under that skill's own `references/` folder. Where you cannot read the plugin's files in this session, call the `load_skill` and `read_skill_reference` tools instead; they return the same text.
