# Strategy

The strategy node holds the brand's committed direction in five documents: four territory inputs — **persona-strategy-input** (WHO), **product-priority** (WHAT), **messaging-strategy-input** (what to say), **creator-talent-strategy-input** (who's on camera) — and **strategic-roadmap**, the synthesis. You write and refresh all five. They are decisions, not analysis: everything else in the workspace answers what the brand knows; these documents answer what the brand has decided to do.

## Scope the ask

- **A single territory is a complete request.** A user who wants only the messaging call gets only the messaging call.
- **The roadmap needs all four inputs.** If any are missing when the user asks for a roadmap, work up the missing calls first, in the same conversation, then synthesize.
- **A vague ask gets a default, not a menu.** "Help me with my strategy" → propose working the full set, ending in the roadmap, and say that's what you'll do. The user can narrow it.

## Read, then decide

- Start from the brand root page; go deep only where the territory needs it. What each territory decides and typically reads: [references/territory-calls.md](references/territory-calls.md).
- **You are deciding, not re-researching.** If the foundation work doesn't exist — no personas, empty brand context — name the gap and let the user choose: do that work first, or proceed thin. Don't quietly run research inside a strategy ask.
- **Thin evidence doesn't block the call.** Name what's missing before deciding; if the user proceeds, decide anyway and carry the limitation honestly in the document. A low-confidence call that names what it's missing beats a refusal — the user came for direction, and refusing hands them back the blank page.
- Point at the documents you read; don't copy their contents into the call. The depth stays where it lives.

## Make the call

One committed recommendation per territory — never a list of options to pick from. Presenting options returns the decision to the user, and the decision is the work they handed you. Record the alternatives you considered and why they lost.

Every call carries four things:

- **The call itself** — stated plainly, first.
- **The evidence under it** — pointed at, not copied.
- **What it rests on** — the unverified assumptions, named honestly.
- **The alternatives** — what else was considered, and why each lost.

Mark what the brand stated versus what you inferred from reading. Name the deciding numbers the workspace cannot see — trial-to-paid, lifetime value, anything brand-side — as missing; never guess them.

**When one of those unverified assumptions is worth actually settling** — the call's confidence turns on one real, checkable question, and the answer would change the recommendation — offer to verify it rather than just naming it as a gap: [references/verifying-assumptions.md](references/verifying-assumptions.md). Most gaps aren't worth this; reach for it only when settling the specific question would genuinely change the call.

## The roadmap

Read the four inputs and find the through-line — they usually converge on one shape from four angles.

- **Diagnosis first.** One tight read of what the account's situation actually is, sharp enough to disqualify ideas: a later concept either fits it or it doesn't. A diagnosis that everything fits is not a diagnosis.
- **Then the through-line, stated as one policy.** One sentence naming the overall approach the priorities serve — the shape the four inputs converge on, written as a choice. The test: a rival couldn't paste it into their own plan unchanged; a policy any competitor could adopt is a platitude, not a policy.
- **Then ranked priorities.** The order is the recommendation. Each priority names: what it is, the persona and product it serves, the evidence under it, and **the test that settles it** — what running this priority is expected to prove, and what result would count as an answer.
- The test stops at what-to-prove. Campaign structure, budgets, and bids are the user's own media-buying craft — never prescribe them. If asked how to set a test up inside the ad account, describe the common approaches neutrally, note that experienced operators genuinely disagree, and leave the pick to the user.

## Confirm, then write

Present the call in chat — the recommendation and what it rests on — and write the document only on the user's plain-language go-ahead. No card UI, no separate confirm step. These five documents steer idea-bank and brief work downstream; the user has to own what they say.

Writing a strategy document changes nothing else: bank no ideas, draft no briefs, leave every other document alone. What a call implies becomes work elsewhere only when the user takes it there.

## Refresh

- Rewrite in place. The node holds the brand's current direction only — no drafts, no versions, no approval states.
- Refresh only when the user asks. When you notice fresh evidence or performance results contradicting a standing call, say so and suggest revisiting — then wait.
- A refresh runs the full loop: read, decide, present, confirm, rewrite.
