# Research

This is one of ViralMojo's four companion skills. The standing rules and host routines every ViralMojo skill assumes — confirm before writing, never invent, the workspace anchor, job polling inside 45 seconds — live in `$viralmojo`: load it first if it is not loaded in this session.

Pick the one skill below whose description matches the request and, before doing the work, call the ViralMojo `load_skill` tool with its name; follow the instructions it returns. They are the web agent's own, served by ViralMojo, so they are always the deployed ones. Load one skill for the work in front of you, not every skill the ask brushes against.

| Skill | What it does and when to use it |
|---|---|
| `evidence-mining` | Digs public channels — the open web (practitioner posts, articles, blogs), Reddit, LinkedIn, Facebook pages, groups and page reviews, App Store reviews, TikTok Shop reviews, Amazon reviews, YouTube, X/Twitter, review sites, brand and competitor websites — for verbatim, sourced customer and market evidence including quotes, complaints, switching stories, niche language, how a kind of person does a thing and why, competitor discovery, and competitor deep-dives. Use when the user asks to research or dig into a topic, find quotes, reviews, complaints, or what people say about a brand, product, category, or audience, or to find new competitors or analyze a named one — whether they name a channel or leave the choice open. Not for first-party reviews or surveys the user uploads; those are customer evidence. |
| `customer-evidence` | Ingests and maintains a brand's own first-party customer evidence — its store and marketplace reviews, and its post-purchase survey responses — which come from the user, the one exception being the reviews of the brand's own Amazon or TikTok Shop listing, pulled on the user's ask. Use when the user shares reviews or survey responses in any shape (exports, spreadsheets, screenshots, pasted text), asks to keep the reviews of the brand's own Amazon or TikTok Shop listing, or asks to correct, update, or remove saved reviews or survey answers. |
| `content-search` | Searches TikTok and Instagram Reels for content — viral videos, niche creators, formats and hooks worth studying — returning one curated, browsable collection the user can save from into the swipe file. Use when the user asks to find, search, or pull videos, reels, or TikToks on a topic, angle, brand, or trend. Not for links the user pastes (those parse on their own) and not for text-evidence digs into quotes, reviews, or complaints — this finds watchable reference content. Also the home of saved queries — use when the user wants an angle watched on an ongoing basis ("keep an eye on", "every week", "track", "add a query") or wants to drop one, and when a one-off search proves rich enough to keep. |
| `link-parse` | Handles TikTok, Instagram Reels, and Meta Ad Library links pasted into chat — resolves the link immediately into its full workspace record and returns a clickable card the user can open and save to the swipe file. Use whenever a message contains a link from one of those three platforms, with or without surrounding text. Not for general web URLs — only these three content platforms. |
| `video-deep-read` | Runs a fresh, targeted read of one video's actual frames and audio, for a question the video's fixed pre-processed context can't answer — a specific visual or on-screen detail, a storyboard or pacing walkthrough, or any video that has no pre-processed record yet: freshly uploaded, never tagged, or a video the user just attached in chat. Use only when the fixed context doesn't already cover what's asked; check it first, don't re-read a video for something already there (an attached video has no fixed context, so read it directly). |

Where a skill points at a reference file (`references/<file>.md`), read it with `read_skill_reference`, the skill's name and the file name; `load_skill` lists the files. Where it says to call `load_skill` with another skill's name, call it — the skill may sit in another companion (`$research`, `$creative`, `$strategy` or `$performance`), and the tool loads it either way. If `load_skill` answers that the skill is not available, tell the user plainly that this capability is not open on their account yet, and do not improvise it.
